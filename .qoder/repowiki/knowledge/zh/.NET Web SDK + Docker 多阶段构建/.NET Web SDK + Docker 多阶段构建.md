## 1. 构建系统概览

本项目采用 .NET Web SDK（`Microsoft.NET.Sdk.Web`）进行编译，目标框架为 `net10.0`。没有自定义 Makefile、MSBuild 脚本或 CI 流水线；构建与发布通过 `dotnet publish` 完成，容器镜像由单文件 `Dockerfile` 定义。

项目结构是扁平的 Blazor Server 应用：一个 `.csproj` + 一个 `.slnx` 解决方案文件（`vehicleManagement.slnx`），无多项目拆分，所有依赖在 `vehicleManagement.csproj` 中声明。

## 2. 关键文件

- `vehicleManagement.csproj` — 项目定义、TargetFramework、NuGet 包引用（EF Core Sqlite、FluentUI、Serilog、SemanticKernel、Ollama 连接器等）。
- `Dockerfile` — 三阶段构建：`base`（aspnet:10.0）、`build`（sdk:10.0，执行 restore → publish）、`final`（运行时镜像，安装 curl 用于 HEALTHCHECK）。
- `.dockerignore` — 排除 `bin/obj/data/logs/Folder`、`.git`、`*.dbmdl`、`**/*.*proj.user` 等，避免把本地构建产物和敏感数据打入镜像。
- `vehicleManagement.slnx` — 仅引用单个 `vehicleManagement.csproj`。

## 3. 构建与发布流程

### dotnet 构建
- 使用 SDK 默认目标：`dotnet build` / `dotnet run` / `dotnet publish`。
- `Program.cs` 作为统一启动点，装配 vehicle_management_app、ai_chat_subsystem 与 static_assets 三个子模块。
- EF Core Tools (`Microsoft.EntityFrameworkCore.Tools`) 以 `PrivateAssets=all` 引用，仅在开发/设计时可用，不进入运行依赖。

### Docker 多阶段构建
- `ARG BUILD_CONFIGURATION=Release`，默认 Release 构建。
- 先 `COPY *.csproj` + `dotnet restore`，再 `COPY . .` + `dotnet publish -c $BUILD_CONFIGURATION -o /app/publish /p:UseAppHost=false`，利用 Docker 层缓存加速后续构建。
- 最终镜像基于 `mcr.microsoft.com/dotnet/aspnet:10.0`，暴露端口 80，设置 `ASPNETCORE_URLS=http://+:80`。
- 通过 `ENV AiServer__OllamaEndpoint=${OLLAMA_ENDPOINT}` 和 `AiServer__OllamaModel=${OLLAMA_MODEL}` 注入 AI 配置，支持 `--build-arg` 或 `docker run -e` 覆盖。
- 持久化目录 `/app/data`、`/app/logs`、`/app/Folder` 通过 `VOLUME` 声明，需外部挂载。
- HEALTHCHECK 调用 `curl -f http://localhost/health`，要求应用提供 `/health` 端点。

## 4. 约定与约束

- **目标框架固定为 net10.0**（`vehicleManagement.csproj` 中 `<TargetFramework>net10.0</TargetFramework>`）。
- **不使用自宿主 exe**：publish 参数 `/p:UseAppHost=false` 生成纯 DLL 部署（`vehicleManagement.dll`），由 `ENTRYPOINT ["dotnet", "vehicleManagement.dll"]` 启动。
- **AI 配置必须通过环境变量注入**：`AiServer__OllamaEndpoint` 与 `AiServer__OllamaModel` 在 Dockerfile 中以 ARG+ENV 形式声明，部署时需显式传入。
- **数据与日志不内嵌镜像**：`data/`、`logs/`、`Folder/` 被 `.dockerignore` 排除并在运行时通过卷挂载。
- **镜像健康检查依赖 curl**：运行时镜像在安装阶段 `apt-get install -y --no-install-recommends curl`，若基础镜像变更需同步维护。
- **Logo 资源不参与构建**：`Folder/logo/**` 在 csproj 中被 Remove 掉 Compile/Content/EmbeddedResource/None，说明 logo 应通过外部方式提供。
- **解决方案极简**：`vehicleManagement.slnx` 只包含一个 Project 条目，无复杂 Solution 级属性或条件构建。

## 5. 缺失项

仓库中未发现 CI/CD 配置文件（如 GitHub Actions `.github/workflows/`、Azure DevOps YAML、Jenkinsfile 等），也未见 Makefile、build.sh、release 脚本或版本管理策略文件。构建与发布目前停留在本地 `dotnet publish` + Docker 构建层面。
